# ПЗ №1. Middleware и шаблонизаторы — «Тихая гавань»

Сервис анонимной психологической поддержки: обращения за консультацией и тесты для самопроверки.
Express.js + EJS, данные хранятся в файле `data\consultations.json` (без БД).

## Запуск

```bash
npm install
npm start
```

Открыть http://localhost:3000. Порт меняется переменной `PORT`.

## Страницы и маршруты

| Маршрут | Описание |
|---|---|
| `GET /` | список обращений, фильтр `?category=` |
| `GET /item/:id` | детальная страница обращения |
| `GET /add`, `POST /add` | форма нового обращения (только после входа) |
| `GET /tests`, `GET/POST /tests/:slug` | психологические тесты |
| `GET /my` | «Мои обращения» (только после входа) |
| `GET /login`, `POST /login` | вход по псевдониму и коду доступа |
| `POST /register`, `GET /welcome` | регистрация уникального псевдонима, однократный показ кода |
| `GET /logout` | выход (сессия удаляется на сервере) |
| `GET /no-such-page` | демонстрация страницы 404 |

Ссылка на страницу 404 есть в подвале каждой страницы. Страница 500 вызывается не кнопкой, а реальным сбоем хранилища (см. ниже).

## Middleware

- `middleware/logger.js` — метод, URL и время запроса в консоль и в файл `logs/requests.log` (папка и файл создаются автоматически, если их удалили; при невозможности записи — страница 500).
- `middleware/auth.js` — авторизация: по cookie сессии определяет `req.user`, без входа `req.user = { name: 'Гость' }`; `requireAuth` редиректит на `/login`.

## Анонимная учётная запись

- Пользователь выбирает **уникальный псевдоним** и получает **код доступа** `XXXX-XXXX` (показывается один раз).
- Повторный вход — псевдоним + код; в `data/users.json` хранится только хеш кода (scrypt + соль).
- Псевдоним нельзя занять повторно: не учитываются регистр, пробелы, `_`/`-`, похожие латинские и русские буквы;
  смешивать алфавиты нельзя; занятыми считаются и псевдонимы авторов уже существующих обращений.
- Защита от подбора: 10 неверных попыток входа за 15 минут с одного IP → 429; регистраций — 5 в час.
- Сессия — случайный токен в httpOnly-cookie; подделать вход, изменив cookie, нельзя.
- Автор обращения берётся из сессии, а не из формы; e-mail обращения виден только автору.
- `middleware/viewLocals.js` — пользователь и хелперы (`formatDate` и др.) для всех шаблонов.
- `middleware/errorHandlers.js` — 404 (`404.ejs`) и обработчик ошибок с 4 параметрами (`500.ejs`): системные ошибки переводятся в пользовательские сообщения, технические детали пишутся только в `logs/errors.log` и консоль; при сбое шаблона — запасной HTML.

## Как вызвать страницу 500 (демонстрация)

Данные хранятся в `data\consultations.json` (роль «БД»), файл перечитывается при каждом запросе.

| Действие (при запущенном сервере) | Результат |
|---|---|
| `icacls data\consultations.json /deny %USERNAME%:(R)` | 500 «Ошибка доступа к хранилищу данных: нет прав» |
| заменить `data\consultations.json` папкой с тем же именем | 500 «по этому пути находится папка, а не файл» |
| записать в `data\consultations.json` некорректный JSON | 500 «Файл данных обращений повреждён» |
| `attrib +r data\consultations.json` и отправить форму | 500 «Не удалось сохранить данные» |
| `attrib +r logs\requests.log` | 500 «Ошибка доступа к журналу запросов» |
| создать папку `logs\requests.log` или файл `logs` вместо папки | 500 с описанием проблемы |
| удалить/переименовать `logs\requests.log` или папку `logs` | файл и папка создаются заново, сайт работает |
| удалить `data\consultations.json` | файл восстанавливается из копии в памяти |

Вернуть права: `icacls data\consultations.json /remove:d %USERNAME%`, `attrib -r <файл>`.

## Защита от некорректного ввода

- размер тела формы — не более 20 КБ (413), не более 30 полей; длина URL в логах и на страницах обрезается;
- в полях запрещены управляющие и невидимые символы (нулевой байт, zero-width space и т.п.);
- слишком длинные числа (вставка «999…») отклоняются до преобразования, запись вида `1e5` не принимается;
- поддельные значения (массивы `title[]=`, неизвестные варианты select/radio) отклоняются;
- битые cookie и некорректная кодировка в адресе (`%E0%A`) не роняют сервер (400 с понятным текстом).

## Ограничения ввода (`config/limits.json`)

Все числовые ограничения (длина и диапазоны полей, длина псевдонима, размер тела запроса и число полей,
попытки входа, срок жизни сессии) вынесены в `config/limits.json`. Файл проверяется при запуске:
если он удалён, повреждён или содержит недопустимые значения, сервер не стартует и пишет причину в консоль.

## Валидация формы обращения (`validators/`)

- обязательные поля: пустое значение и значение из одних пробелов отклоняются;
- ограничения длины: тема 5–100, псевдоним 3–30, описание 20–1000, e-mail до 100 символов;
- числовые поля только целые и ≥ 0: возраст 14–100, уровень тревоги 0–10, длительность 15–120 (кратно 15);
- направление и формат — только из справочника; псевдоним — буквы одного алфавита, цифры, пробел, `_`, `-`;
- текст должен содержать буквы и не содержать длинных повторов одного символа;
- необязательный e-mail проверяется по формату, если заполнен;
- запрет дубликата (у одного автора не может быть двух обращений с одинаковой темой), обязательное согласие;
- для различения записей у каждой выводится уникальное время создания (с миллисекундами).

## Структура

```
server.js            точка входа, порядок middleware
config/              limits.json — все ограничения ввода, limits.js — их загрузка и проверка
routes/              маршруты
controllers/         обработчики маршрутов
models/              обращения и учётные записи (JSON-файлы)
validators/          правила и валидаторы форм
middleware/          кастомные middleware
utils/               хелперы, asyncHandler, AppError, fileLog
views/               EJS-шаблоны (partials/header, partials/footer)
public/              CSS и JS
data/                consultations.json, users.json, tests.js
```
